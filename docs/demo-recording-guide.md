# Сценарий съёмки демо-видео (2–4 минуты)

> Артефакт №6 по `InitialTask.md`: **демо-видео 2–4 минуты — ключевой сценарий + аудит + ручная проверка**.
> Видео записывается по этому сценарию; каждый шаг соответствует уже готовым скриншотам
> в [`docs/screenshots/`](../docs/screenshots/) (можно показать их как вставки, если живой LLM недоступен
> при съёмке).

## Перед съёмкой (чек-лист)

- [ ] `docker-compose up --build` → backend `http://localhost:8000/docs`, фронт `http://localhost:3000`
- [ ] Данные для показа уже загружены: войти как `admin` → **Настройки → «Загрузить примеры для всех процессов»** (seed) — появляются 10+ ТЗ, 5 KB-статей, история вопросов. Либо использовать готовые данные из dev-БД (скриншоты сделаны на них).
- [ ] Провайдер LLM настроен: «⚡ Тест связи» = OK (облачный ключ или локальный Ollama `qwen2.5:7b`; для локального CPU-модели выставляйте `LLM_TIMEOUT=2400`).
- [ ] Вкладка браузера чистая (не инкогнито — нужен localStorage), размер окна ≥ 1440×900.
- [ ] Запись экрана: OBS / Гудиин / встроенная запись экрана. Разрешение 1280×720+.

## Что обязательно показать (требования InitialTask)

- [ ] **Успешный сценарий** — кадры 2–4 (рецензия с полным отчётом, `needs_review=false`).
- [ ] **Ручная проверка (метка + причина)** — кадры 5–6 (фильтр «Требует проверки», жёлтая плашка причины `NO_SOURCES_FOUND` / `LOW_CONFIDENCE`).
- [ ] **Витрина данных** — кадры 2–3, 5 (списки документов и рецензий).
- [ ] **Экспорт (JSON или CSV)** — кадр 4.
- [ ] **Аудит** — кадр 7.
- [ ] **Оба варианта проекта** — кадры 3–4 (Вариант 2) и 6 (Вариант 5).
