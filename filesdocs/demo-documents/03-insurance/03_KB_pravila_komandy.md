# Правила работы команды — проект «СтрахПортал»

## Изменение тарифных правил

- Любое изменение тарифа, которое продуктовая команда вносит через конструктор продуктов,
  автоматически создаёт новую версию продукта — редактирование «на живую» действующей версии,
  по которой уже есть оформленные полисы, запрещено на уровне системы.
- Изменения в коэффициентах ОСАГО вносятся только на основании официальной публикации Банка
  России, с указанием ссылки на источник в комментарии к версии продукта.

## Работа с интеграцией АИС ОСАГО

- Любой сбой передачи данных в АИС ОСАГО — инцидент P0 (это законодательно обязательная
  интеграция), эскалация ответственному за интеграции немедленно.
- Тестирование изменений в модуле ОСАГО проводится только на тестовом контуре РСА, не на проде.

## Урегулирование убытков

- Специалист по урегулированию обязан зафиксировать статус заявления в системе в тот же рабочий
  день, когда принято решение — просрочка фиксации статуса не должна использоваться как способ
  скрыть нарушение SLA по срокам рассмотрения.
- Расчёт выплаты всегда идёт по условиям полиса на момент его оформления, а не по текущей версии
  продукта — это правило имеет приоритет над любыми более поздними изменениями тарифа.

## Комплаенс и аудит

- Все изменения тарифных правил логируются с указанием пользователя и обоснования — эти логи
  предоставляются регулятору по запросу и не должны редактироваться задним числом.
- Доступ к конструктору продуктов есть только у продуктовой команды и её руководителя; у
  разработчиков — только просмотр, без права изменения действующих тарифов.
